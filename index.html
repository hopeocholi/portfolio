How I work

Just enough process to keep control, never so much that it slows the team down.

  1. Start with the case

    A short business case and a clear use case before any build, so the decision to start is a real one.

  2. Govern in proportion

    Light controls for small changes, phase gates for big ones, and AI risk checks with human review where models are involved.

  3. Report honestly

    One status view for leadership: progress, risks, issues and decisions needed, from the same RAID log every week.

  4. Learn on purpose

    Lessons learned at every stage end, and each one changes a template or checklist for the next project.
